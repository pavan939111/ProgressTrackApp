## UX Review (Critical)

Based on the product vision, these wireframes should NOT be considered the final UX. There are several improvements that should be made before moving to high-fidelity UI.

**1. Dashboard should become an "Action Dashboard"**

The current dashboard still resembles a task manager. Instead, the first screen should emphasize:
- Current Focus
- Current Session
- One Primary Action: "Continue Working"

Historical information should move lower on the screen.

**2. Planning should be a Wizard**

Instead of one long planner page:

```
Step 1 → Weekly Goal
      ↓
Step 2 → Tomorrow's Goal
      ↓
Step 3 → Morning Tasks
      ↓
Step 4 → Afternoon Tasks
      ↓
Step 5 → Review
```

This reduces planning fatigue.

**3. Progress Update should be ultra-fast**

A reminder should open a lightweight card where the user can finish the update in under 30 seconds, using mostly taps instead of typing.

**4. Dashboard should dynamically change throughout the day**

- Morning: Show Morning Session.
- Afternoon: Automatically switch to Afternoon Session.
- Evening: Focus on remaining work.
- Night: Transition into Tomorrow Planning.

The dashboard should evolve with the day instead of remaining static.

**5. Reports should be read-only**

Reports should act as historical snapshots. Any edits should happen in the Planner or Tasks, not inside report screens.

**Recommendation:** Before creating high-fidelity UI or implementing components, the next document should be a UX Flow & Interaction Design Specification, defining every user interaction, state transition, gesture, animation trigger, modal, and navigation behavior. This will remove almost all ambiguity during frontend development.
